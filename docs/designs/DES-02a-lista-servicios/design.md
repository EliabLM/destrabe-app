# DES-02a — Diseño del listado propio

- Shared Zod valida la query estricta y define la respuesta; app y backend importan el mismo contrato. El cursor se codifica como base64url canónico de JSON `[createdAt.toISOString(), id]` (sin identidad); el backend valida forma, fecha canónica e id antes de consultar. No es cifrado ni firma: solo opacidad de transporte; no contiene secretos.
- Router `GET /` antes de `/:id`: `requireAuth`, `requireRole(CLIENT)`, `validate` → `ClientProfile.findUnique({ userId: req.user.id })` → `Service.findMany` con `clientProfileId` fijo, predicado `createdAt < cursor.at OR (createdAt = cursor.at AND id < cursor.id)`, `orderBy DESC,DESC`, `take=limit+1`. La fila extra detecta `nextCursor`. Selección explícita de campos; fechas serializadas ISO.
- App: `apiServices.listMyServices(cursor?)` devuelve envelope. `servicesPager` incrementa páginas, deduplica ids, retiene cursor y error para reintento y usa generación + identidad `user.id:token` para descartar respuestas antiguas. Pantalla refresca al foco y pull, carga al final y presenta error sin renderizar estado vacío. El interceptor Axios no borra una sesión nueva al recibir un 401 tardío de otra.
- Compatibilidad: no cambia POST, `/nearby`, `/:id`, schema/migraciones ni roles. `ActiveServiceScreen` consumía la antigua forma array del endpoint inexistente; se adapta el acceso al envelope para tipos, pero su flujo OPERATOR sigue sin endpoint propio de asignados (fuera de alcance).
- Verificación: unit/HTTP Supertest con mocks de bordes, prueba de paginador y adaptador Axios con mocks, más prueba HTTP sobre Postgres aislado en CI para filtro y orden. No equivale a prueba de dispositivo ni a test local de Postgres.
